# DB変更・データメンテナンス方針

更新日：2026-10-03。基本方針は合意済み。実際のスキーマ・運用スクリプトは未実装。

## 正と生成の方向

Flyway SQL → 一時DBへ適用 → jOOQコード生成 → Javaコンパイル → 永続化試験の順に実行する。本番DBや手修正した開発DBをコード生成の正にしない。ドメインモデルは業務を表し、DBのRecordと別に設計・変換する。

変更PRには、業務ルール/モデル、マイグレーション、jOOQ再生成による影響、repository/query、API/SDK、既存データ移行、旧新版互換性と復旧方法の該当範囲を含める。列削除や型変更はコンパイルでも検出できるが、意味の取り違えや保存漏れは結合試験で確認する。

## 資材の区分

| 種類 | 配置 | 実行 |
|---|---|---|
| DDL、全環境必須のマスタ、リリース必須の小規模データ変換 | `backend/src/main/resources/db/migration/` | Flyway |
| 大規模backfill | `backend/db/maintenance/<日付>_<目的>/` | リリースの必須工程として明示し、完了検証後に次段階へ進む |
| 個別データ訂正・再集計 | 同上 | 対象環境を指定して手動開始 |
| 開発・試験データ | `backend/db/fixtures/` | 開発/試験専用。Flyway本番locationsに含めない |
| パスワード等の環境固有設定 | Secrets Manager等 | SQL/Gitへ埋め込まない |

Flywayの版付きSQLの命名案は`V20261003180000__create_reservation.sql`。時刻部分はUTCで統一し、同時刻の衝突はCIで拒否する。実際の適用順は版番号順で、マージ順とは限らない。release分岐後のhotfix等で順序逆転がないか、現行本番からの移行試験で確認する。共有環境へ適用済みの版付きSQLは編集せず新しい版で訂正する。outOfOrderは初期無効を基本とし、古い版の後入れを黙って適用しない。

初期マスタは「アプリに必須のコード定義」と「運営が変更する料金・地域設定」を分ける。後者の本番値を開発用seedで上書きしない。各業務モジュールが変更を所有するが、基幹DBのFlyway履歴は初期1系統で統合する。

## メンテナンス資材

日付フォルダにREADME、precheck.sql、apply.sql、postcheck.sql、必要な変換スクリプトを置く。READMEは対象/前提版/想定件数/実行権限/順序/再実行条件/中断復旧/検証を持つ。

大量処理は小分け更新、再開位置、再試行・重複実行の扱い、ロック時間を設計する。実行ログに環境・操作者・コミット・件数・時刻を残す。原本CSVやログに個人情報があればアクセス制限したS3へ置き、Gitには入力仕様・参照方法・ハッシュを残す。

## 旧新版共存とリリース

ECS rolling更新では旧・新タスクが共存する。基本はexpand → migrate/backfill → switch → contract。

1. 旧版にも許容される列/テーブル追加を先行する。
2. 旧版の更新を取りこぼさない同期方法（段階的dual-write等）を用意してデータ移行する。
3. 新版の読取/書込へ切り替え、欠落と互換性を確認する。
4. 旧版への復帰が不要となった後続リリースで列削除/制約強化を行う。

変更の種類に応じて手順を具体化する。NOT NULL追加、enum変更、列名変更、インデックス作成はロック・実行時間・旧版の挙動も確認する。DDLのトランザクション可否はDBと命令によるため、途中失敗時の残存状態を明記する。

DB移行はCD中の専用単一ジョブ（例：ECS one-off task）で実行する。通常アプリの全レプリカから自動起動しない。移行権限と通常DML権限を分け、成功後にECSを更新する。ただし後段backfill等が必要ならリリース手順で順序を上書きする。

## 検証と復旧

- 空DBに全適用できること、現行本番版＋代表データから更新できることを確認する。
- 旧アプリが拡張後DBを使えること、新アプリが移行途中にどう振る舞うかを確認する。
- Flyway validateは履歴/チェックサム検証。手動DDLを含む実スキーマの全差分検出ではない。通常の直接DDLを禁止し、必要なら別のスキーマ差分検査を導入する。
- アプリ復旧は互換DB上で旧成果物を再配置する。DBの自動逆マイグレーションを前提にしない。
- データ損失がある場合はforward fixかバックアップ/PITRから別クラスタへ復元して切替する。復元で失う更新、停止時間、復旧確認を事前に評価する。
