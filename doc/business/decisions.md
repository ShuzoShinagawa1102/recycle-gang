## 決定事項

### DEC-20261001-01：定期便を中心に予約・回収を運営する

- 日付：2026-10-01（日本時間）
- 状態：品川が提示した現時点の方針。詳細な運用条件は未決事項を含む。
- 背景：顧客は早さ、日時の分かりやすさ、信頼性、安さを重視し、作業員選びや細かな料金比較の負担を減らしたい、という顧客仮説。
- 決定：地域の定期便を中心に枠へ予約を集め、運営が業者手配と回収順序を管理する。
- 関連：[ビジョン](vision.md)、[サービスのコンセプト](service-concept.md)。

| 項目 | 今回記録した方針 |
|---|---|
| 定期便 | 週3回程度を目安とし地域差を認める。2週間前から予約枠を公開可能とする。 |
| 支払い・確定 | 先払い、「予約前日で確定」、キャンセル料なし。前日の基準・確定対象などは未決。 |
| 業者手配 | 回収日の3日前から、現時点の予約＋追加予約予測をもとに業者数・オファーを決めて通知・募集する。 |
| 当日の回収 | 運営側で経路・住所順を計算して提示し、その順で回収する。指定場所に回収品を搬入し、バックヤードアプリで成果を逐次記録する。 |
| 優先順位 | 即時オファーよりも、運営が手配した予約分を優先してもらう。 |
| SOS | 事故・遅延などのSOSを受けて別業者へオファーし、SOS対応業者にオファー金額の30%を渡す。計算元・原資は未決。 |
| 即時依頼 | 通常料金＋追加料金。登録業者へ通知し、募集額を段階的に引き上げる。上限ルールは非公開。3時間前の期限で不成立なら利用者に通知するが、基準時刻は未決。 |
| 将来機能 | 対面で時間をかける解体作業などの専用枠を、定期便方式で後から追加する。 |

条件の正は[業務ルール](business-rules.md)、手順は[業務フロー](workflows.md)、実装要件の概要は[要件](requirements.md)に置く。

## 検討中・保留事項

- 「予約前日で確定」「オファー時刻前3時間前」「SOSの30%」について、原文の意図を維持して具体的な計算・期限の確定を保留する。
- 顧客ニーズの見立ては未検証の仮説として扱う。
- 公的な信頼性をどう担保するかは未決。認定取得済みとは扱わない。
- 決済・返金、業者不足時の対応、経路の変更、報酬の配分などは[Q-01〜Q-09](business-rules.md)に集約する。
- 初期リリース範囲は[対象範囲](scope.md)を参照。
